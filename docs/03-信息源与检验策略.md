# SignalRadar 信息源与检验策略

| 项目 | 内容 |
| --- | --- |
| 版本 | v1.0 |
| 日期 | 2026-11-04 |
| 原则 | 质量 > 数量；官方/一手优先；广度源只做发现信号 |
| 实测环境 | 本地 Windows / Python 3.13 / httpx 0.28 |

## 1. 信息源分层

| 层级 | 定义 | 最高可信等级 | 推送 |
| --- | --- | --- | --- |
| 官方/一手 | 模型厂商、项目官方博客、官方 Release | `verified` | 达到阈值可推送 |
| 官方项目发布 | GitHub Releases、产品 Changelog | `verified` | 达到阈值可推送 |
| 研究 | HF Daily Papers、论文/基准 | `likely` | 达到阈值可推送（标为研究） |
| 媒体 | 高质量科技/开发媒体 | `verified`（需多源或官方） | 达到阈值可推送 |
| 社区 | V2EX、掘金、SegmentFault、B站 | `unverified` | 不自动推送 |
| 热榜信号 | 泛热搜/热榜 | `unverified` | 不自动推送 |

> 社区与热榜的内容即使 AI 给出很高可信度，也不会自动升级为 `verified`，更不会触发 Webhook。

## 4. 检验策略

### 4.1 采集前过滤

- 通用媒体、社区、B站、掘金、V2EX 先做 AI 关键词预过滤，避免把泛新闻送进模型。
- 关键词包括 AI、大模型、LLM、GPT、Claude、Gemini、Qwen、DeepSeek、Agent、MCP、编程、代码、开源、芯片、GPU、推理等。
- 官方 AI 源（OpenAI/Qwen/HF 等）不做预过滤，避免漏掉标题不含关键词的官方内容。

### 4.2 去重与聚类

- URL 规范化，去除跟踪参数。
- 标题相似度 = 字符序列相似度 × 0.6 + 词/Jaccard × 0.4；阈值 0.86。
- 回看 72 小时；同一事件多源合并，来源域名写入 `also_sources`。
- 多个独立域名印证时提升可信度，但社区/热榜的等级封顶仍然生效。

### 4.3 可信等级封顶

| 来源层级/内容类型 | 最高等级 | 可信度上限 |
| --- | --- | --- |
| 官方/一手 | `verified` | 按评分 |
| 官方项目发布 | `verified` | 按评分 |
| 研究论文 | `likely` | 90 |
| 媒体 | `verified`（需官方或多源） | 按评分 |
| 社区 | `unverified` | 60 |
| 热榜信号 | `unverified` | 60 |
| 传闻/营销 | `unverified` / 更低 | 42–58 |

### 4.4 推送策略

- 只有 `verified` / `likely` 且可信度达到阈值才写 Webhook。
- `unverified` / `suspicious` 只进站内电报。
- 社区/热榜永远不自动推送。
- 浏览器桌面通知只对 `critical` / `warning` 弹出。
- 单关键词单轮最多 3 条告警（可配置），避免刷屏。

### 4.5 时效

- 范围热点默认近 7 天。
- 关键词巡检默认近 48 小时。
- 无发布时间的内容允许进入，但会显示“时间未知”；旧闻翻炒由 AI + 来源判断降级。

### 4.6 关键词查询扩展与匹配等级

- 每个关键词生成 2–5 条扩展查询：完整短语、别名、核心锚点组合。
- 查询计划必须通过规则校验：锚点来自原文，别名不得包含原关键词没有的版本号。
- 先做锚点门禁：`none` 丢弃，`weak` 入库不告警，`partial` 入库不告警，`exact/strong` 才进入告警候选。
- 例：`Claude Sonnet 4.6` 要求 `Claude + Sonnet + 4.6` 或别名 `Sonnet 4.6`；只出现 `OpenClaw` 或 `Claude Code` 不算相关。
- 电报展示匹配等级、命中锚点、原文证据和匹配理由。
- 评估入口：`scripts/eval_keyword_quality.py` 与 `evals/keywords/*.jsonl`；硬负例同时进入 pytest。

| 源类型 | 每轮上限 |
| --- | --- |
| 通用媒体 | 4 |

| GitHub Releases | 4 |

这样可以在增加广度的同时控制 LLM 调用时间和噪声。

## 6. 如何调整

- RSS 源与元数据：`app/config.py` 的 `DEFAULT_FEEDS`。
- 自定义 JSON 源：`app/config.py` 的 `CUSTOM_SOURCES` 与 `app/sources.py` 的适配器。
- 层级/内容类型：`source_tier`、`content_kind`。
- 封顶规则：`app/pipeline.py` 的 `_cap_verdict` 与评分函数。
- 关键词预过滤：`app/sources.py` 的 `AI_HINT_RE`。
