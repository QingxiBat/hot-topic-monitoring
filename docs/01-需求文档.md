## 1. 背景与问题

AI 编程博主需要第一时间获取大模型、AI 编程工具、Agent、开源模型等方向的变化。人工搜索存在三个问题：

1. **慢**：热点出现后再搜索，容易错过最佳发布窗口。
2. **杂**：新闻源多、重复多、标题党多，人工筛选成本高。
3. **假**：同名蹭热度、旧闻翻炒、匿名爆料、营销稿难以快速辨别。

因此需要一个本地优先、可自动运行、能解释判断依据的热点雷达，同时提供可被其他 AI 调用的 Agent Skill。

## 2. 产品目标

### 2.1 核心目标

- 用户输入关键词后，系统持续巡检，发现真正相关的新内容时立即告警。
- 按用户指定的范围（如“AI 编程”）定时采集热点，去重后展示。
- 用本地 `qwen3:8b` 辅助判断相关性、可信度、标题党与假冒风险。
- 提供独特、响应式的 Web 页面，并封装为 Agent Skill。

### 2.2 成功标准

| 指标 | 目标 |
| --- | --- |
| 关键词发现延迟 | 默认定时巡检 10 分钟内；可配置到 2 分钟 |
| 热点展示 | 打开页面即可看到最近 7 天已采集热点 |
| 假冒内容控制 | 可疑内容只入站内，不触发 Webhook 推送 |
| 通知触达 | 页面 SSE 实时提示；高可信内容可推送 Webhook |
| 可解释性 | 每条内容展示来源、可信度、判断依据与原始链接 |
| 可移植性 | CLI 支持 `--json`，可被其他 AI 直接调用 |

## 3. 用户画像与场景

### 3.1 主要用户

**AI 编程博主**

- 关注 AI 编程工具、模型发布、Agent 框架、开源项目。
- 需要第一时间知道“发生了什么”，并快速判断“值不值得发”。
- 不希望被大量低质量推送打扰。

### 3.2 典型场景

1. **关键词蹲守**：输入 `Claude Code`，当出现新版本、新功能、官方公告或高可信报道时收到通知。
2. **每日选题**：打开页面，按“AI 编程 / 大模型 / AI Agent / 开源 AI”浏览最近热点。
3. **爆料核查**：看到一条夸张消息，用 CLI `verify` 判断可信度与假冒风险。
4. **交给其他 AI**：其他 AI 通过 Agent Skill 调用 `scan`、`watch`、`alerts`，自动整理热点简报。

## 4. 产品范围

### 4.1 本期范围

- 单用户、本地运行。
- 公开新闻 RSS / API 聚合，无需商业 API Key。
- 关键词监控与范围热点采集。
- AI 分类、摘要、可信度与假冒风险判断。
- 站内实时通知、浏览器桌面通知、Webhook 推送。
- 响应式 Web 页面。
- Agent Skill CLI。

### 4.2 非本期范围

- 多租户、账号体系、云端 SaaS。
- 全网爬虫与付费新闻源。
- 自动发布到社交媒体。
- 对每条新闻做法律意义上的事实认证。
- 移动 App。

## 5. 功能需求

### FR-01 监控范围管理

- 用户可查看、添加、删除监控范围。
- 每个范围包含名称、查询词、描述、启用状态。
- 默认提供：AI 编程、大模型、AI Agent、开源 AI。
- 删除范围不删除已采集内容。

**验收**：设置面板可新增“AI 芯片”，保存后出现在顶部范围标签中；删除后不再参与采集。

### FR-02 自动热点采集

- 按配置间隔自动采集所有启用范围。
- 数据源包括 Google News RSS、Bing News RSS、Hacker News Algolia、精选 AI 官方博客 RSS。
- 每条内容保存标题、摘要、来源、域名、发布时间、原始链接。
- 支持手动触发采集。

**验收**：启动后自动产生热点；点击“采集新信号”会触发新一轮采集，页面通过 SSE 自动刷新。

### FR-03 AI 分类、摘要与去重

- 使用本地 `qwen3:8b` 判断内容属于哪些范围、相关度、可信度、是否标题党、内容类型。
- 生成简体中文摘要，英文标题也必须翻译。
- 标题相似度聚合，同一事件多源报道时合并并提升可信度。
- 只展示与范围相关且相关度达到阈值的内容。

**验收**：同一事件被两个独立域名报道时，详情中显示“2 家独立来源”；低相关度内容不进入热点流。

### FR-04 关键词哨兵

- 用户可添加、暂停、恢复、删除关键词。
- 系统按配置间隔巡检 Google News、Bing News、Hacker News。
- AI 严格判断是否真的与关键词相关，识别同名、蹭热度、旧闻翻炒、虚构内容。
- 相关且达到阈值的条目生成“电报”告警。
- 单关键词单轮最多生成 N 条告警，避免刷屏。
- 已产生过告警的文章不会重复告警。

**验收**：添加 `Claude` 后，相关新内容出现在电报区；不相关内容不告警；重复巡检不重复生成同一条告警。

### FR-05 分级可信度与反假冒

可信度分四级：

| 等级 | 含义 | 推送策略 |
| --- | --- | --- |
| `verified` 已核实 | 官方来源，或多源印证且分数足够 | 可 Webhook 推送 |
| `likely` 可信 | 来源与模型判断均达到阈值 | 可 Webhook 推送 |
| `unverified` 待核实 | 信息不充分，仅站内展示 | 仅站内 |
| `suspicious` 存疑 | 标题党、高风险、疑似假冒 | 仅站内，标记存疑 |

判断依据：

1. 来源分层：官方域名、头部媒体、中文科技媒体、社区、未知来源。
2. 跨源印证：多个独立域名报道同一事件。
3. AI 审阅：相关度、可信度、标题党、内容类型、假冒风险。
4. 规则约束：传闻、营销稿、耸动词汇会限制最高可信度。

**验收**：官方 OpenAI 公告可达 `verified`；来源不明、标题夸张的爆料为 `suspicious`，不触发 Webhook。

### FR-06 通知渠道

- 站内 SSE 实时 Toast 与电报列表。
- 浏览器桌面通知，需用户授权；只对高可信告警弹出。
- Webhook 支持飞书、企业微信、钉钉、通用 JSON。
- 设置页提供 Webhook 连通性测试。
- 未配置 Webhook 时，高可信内容仍保留站内告警。

**验收**：本地 HTTP 接收器可收到通用 JSON；飞书/企微/钉钉使用各自文本消息格式；测试按钮返回成功或明确错误。

### FR-07 响应式 Web 页面

- 视觉方向：暖色编辑部 / 报纸剪报风，避免通用后台模板。
- 桌面端：主热点流 + 右侧雷达/电报/备忘。
- 移动端：雷达、关键词、电报前置，热点流随后。
- 无横向溢出，设置弹窗可滚动且保存按钮可见。

**验收**：1440px 与 390px 宽度下均无控制台错误、无横向滚动；移动端可完成关键词添加与告警查看。

### FR-08 Agent Skill

- 提供 `.agents/skills/hot-topic-radar/SKILL.md`。
- 提供 CLI：`status / topics / scan / collect / watch / alerts / verify / scopes / keywords`。
- 支持 `--json` 机器可读输出。
- 支持直连本地数据库与 `--api` 调用 Web 服务。
- 支持其他 AI 用来发现热点、布防关键词、核查爆料。

**验收**：其他 AI 可通过 `scan --json` 获取热点列表，通过 `watch --term ... --check` 布防并读取告警。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 及时性 | 关键词巡检默认 10 分钟，可配置最低 2 分钟 |
| 可靠性 | 单个数据源失败不影响其他源；采集任务有锁，避免并发重入 |
| 可解释性 | 每条热点展示来源、可信度、判断依据、原文链接 |
| 隐私 | 默认只监听 127.0.0.1；不提交密钥与本地配置 |
| 噪声控制 | 去重、相关度阈值、单关键词告警上限、分级推送 |
| 兼容性 | 现代 Chrome/Edge/Firefox/Safari；移动端响应式 |
| 可维护性 | 模块拆分、pytest 覆盖、结构化日志与运行记录 |
| 可移植性 | Agent CLI 支持 JSON；Skill 可交给其他 AI 使用 |

## 7. 用户故事与验收标准

### 故事 1：蹲守关键词

> 作为 AI 博主，我希望输入 `Claude Code` 后自动收到相关新消息，而不是手动刷新闻。

- Given 关键词已布防
- When 新一轮巡检发现相关且可信的新内容
- Then 页面电报区出现告警，可信级别足够时触发浏览器通知/Webhook
- And 存疑内容只显示在站内，并标记“存疑”

### 故事 2：浏览范围热点

> 作为 AI 博主，我希望按“AI 编程”查看最近热点，快速决定今天的选题。

- Given 系统已完成至少一轮采集
- When 我点击“AI 编程”范围
- Then 只显示该范围相关热点，按时间排序，带来源、摘要、可信度与原文链接

### 故事 3：核查爆料

> 作为 AI 博主，我希望在转发前判断一条爆料是否可信。

- Given 我有一条标题、来源和摘要
- When 我运行 `radar.py verify ...`
- Then 返回 `verdict / credibility / fake_risk / reason / what_to_check`

### 故事 4：交给其他 AI

> 作为用户，我希望其他 AI 能调用热点雷达，自动整理简报。

- Given 其他 AI 已加载 `hot-topic-radar` 技能
- When 它运行 `scan --scope "AI 编程" --json`
- Then 返回结构化热点数据，包含标题、来源、可信度与链接

## 8. 风险与约束

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本地小模型误判 | 摘要或可信度不准确 | 规则 + 多源印证；页面明确“以原文为准” |
| 数据源限流/失效 | 部分热点缺失 | 多源聚合、失败隔离、可手动重试 |
| 标题党/假冒内容 | 误报 | 来源分层、AI 假冒风险、跨源印证、分级推送 |
| 10 分钟巡检间隔 | 不是秒级 | 可配置到 2 分钟；重要关键词可配合 Webhook |
| 公开 RSS 覆盖有限 | 不保证全网 | 文档明确覆盖范围，不承诺“全网唯一真相” |
| 本地服务暴露风险 | 隐私/滥用 | 默认 127.0.0.1；如需 LAN 访问需自行加认证 |
